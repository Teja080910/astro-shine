User screen fixes

Both apps now read the same tokens, so a screen looks identical whichever role is signed in. Every pair renders in the same mode — switch modes to see light and dark.

Wallet totals: two decimals only

Transactions are stored as Postgres numeric(12,2) but arrive in the app as strings. The wallet screen summed them with Number(t.amount), and binary floating point drifts — 144.64000000000001 is the result of adding values like 0.03, 1.03 and 100 together, not bad data in the database.

Chat input: sits behind the keyboard

The app is built with edgeToEdgeEnabled=true. React Native then calls WindowCompat.setDecorFitsSystemWindows(window, false), which makes the Android window not resize for the IME — windowSoftInputMode="adjustResize" stops having any effect. Content is laid out edge-to-edge, under the keyboard.

  • Root cause: edge-to-edge + setDecorFitsSystemWindows(false). The window is full-height, so nothing shrinks when the keyboard appears. A KeyboardAvoidingView with behavior={undefined} on Android does nothing, leaving the composer underneath the IME.
  • All other screens use ScreenWrapper, which already wraps Android in KeyboardAvoidingView behavior="height". The chat room bypassed it with a bare, iOS-only avoid view.
  • Fix: the chat column now lifts itself by the reported keyboardHeight on Android, and the message list gets flex: 1 so it shrinks and stays scrollable instead of overflowing behind the keyboard.
  • The composer keeps only normal safe-area padding. insets.bottom is already part of the IME height, so adding it again would reintroduce a gap.
  • iOS keeps its KeyboardAvoidingView behaviour="padding" — it overlays rather than resizes, so it needs the padding path.
  • Same bug fixed in 6 other screens that used behavior={Platform.OS === 'ios' ? 'padding' : undefined}: Support (×3), Edit Profile, Astrologer profile edit, and the auth OTP screen.
